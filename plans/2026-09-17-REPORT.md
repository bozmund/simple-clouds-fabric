- **`createFreshLevel` is the wrong API** — it bakes dimensions against the *vanilla*
  datapack overworld, not the selected preset (see `WorldDimensions#bake` registry
  precedence). The working path: run `WorldLoader.load` to obtain a complete, frozen
  `LayeredRegistryAccess<RegistryLayer>` (worldgen + dimensions + dynamic loaded), look up
  the FLAT preset's generator in `datapackWorldgen()`, build a flat `WorldDimensions.Complete`
  via `new WorldDimensions(...).bake(...)`, and **replace the DIMENSIONS layer** with that
  baked registry (vanilla's `openFresh` relies on `WorldDimensions` holding a
  `replaceOverworldGenerator`-ed complete, which a bare preset does not). Then
  `access.createLevelFromExistingSettings(...)`. With the wrong (bare-preset) dimensions the
  integrated server has no `worldgen/*` registries: `Missing registry
  minecraft:worldgen/world_preset`, and every client chunk packet fails with
  `No value with id -1` in `LinearPalette.read` → the client sees an empty void while the
  server has fully generated flat terrain.
- **`ClientLevel#hasChunk` always returns `true` in 1.20.1.** The 7×7 "chunks loaded" gate
  must test `level.getChunkSource().hasChunk(x,z)` (FULL) — otherwise it passes instantly

### How storms work in the original (file:line, step 2.5)

### Port-side gotchas found while wiring CREATEFLAT

- **Ground-relative views (`groundAtTarget`) must resolve `y` from a *computed* heightmap.**
  A merely-present client chunk has an uncomputed `WORLD_SURFACE` heightmap that defaults to
  the min build height, so on the y=-60 superflat it pinned S2/U-01 **underground** (y=-63).
  A `top >= 0` guard also fails (the flat surface is negative), and the client does not load a
  column 800 blocks out to `ChunkStatus.FULL` in 90 s. The fix (in `DevShot`): accept the
  column only when `terrainTop > level.getMinY()` (heightmap computed). 26.2: the min-height
  accessor is `Level#getMinY` (not `getMinBuildHeight`), and `ChunkStatus` lives in
  `net.minecraft.world.level.chunk.status`.
