## Step 0 — frame-watch tool (2026-09-17)

Repo: `/home/jan/nixos-symbiote`. Commit: `1646c63` (no push, per plan).

### What was done

- New Pi extension `packages/pi/extensions/frame-watch/`:
  - `index.ts` — tools `frames_sheet`, `watch_screen`, `watch_video`, `diff_pair`.
    Each returns ONE PNG (base64 content) + a short text summary (frame count,
    mean/max Δ, largest-change pair). All errors are clear text results, never a crash.
  - `sheet.py` — Pillow helper: labelled contact sheets (≤ 2400×2400, per-tile
    `#i name` + `Δ x.x%` vs previous frame, exact via per-value histograms on
    frames scaled to ≤ 512 px) and `A | B | |A-B|×4` diffs (width exactly 3×).
    Protocol: exactly one line of JSON on stdout; `{"ok":false,"error":...}` on domain errors.
  - `test_frame_watch.py` (7 tests) + `test-frame-watch.mjs` (67 assertions; spectacle is a
    stub script, ffmpeg/python real).
- Wiring in `modules/symbiote.nix`: `frameWatchPython` (python3+pillow), runtime inputs
  (`frameWatchPython`, `pkgs.ffmpeg`, `pkgs.kdePackages.spectacle`), launcher exports
  `SYMBIOTE_FRAME_PYTHON/FFMPEG/SPECTACLE` (explicit store paths, no PATH assumptions),
  configurePi symlink, and an assertion tying extension dir + symlink + exports + runtime
  inputs together.
- `flake.nix`: `checks.x86_64-linux.frameWatch` (nodejs_22 + ffmpeg + pillow python).

### Blocker found and workaround used (NOTE for Jan)

1. **HEAD was broken**: commit `0e0f594` ("Phone follows the Konsole chat") left
   `modules/symbiote.nix` with two stray fragments — a `ln -sfn` line inside the
   `adoMcpBinary` attrset (line 587) and a terminal-registry assertion block after
   `environment.systemPackages` — so the committed file does not parse
   (`nix-instantiate --parse` fails). The uncommitted sprite-work fixes this in the
   working tree.
2. **Deploy is blocked by untracked sprite work**: `symbiote-apply` runs
   `nix flake check path:/home/jan/nixos-symbiote`, and flake source nars exclude
   untracked files. The working tree's `flake.nix`/`modules/symbiote.nix` (sprite work,
   not mine) reference untracked `packages/pi/extensions/sprite-gen/`,
   `packages/npu-server/`, `modules/sprite-npu-models.nix` → evaluation fails with
   "To make it visible to Nix, run: git add …". Staging their files is forbidden by the
   plan, so the plain `sudo symbiote-apply` cannot succeed until the sprite session
   stages/commits its work.
3. **Workaround (the apply script's own designed mechanism)**: committed only my step-0
   state (selectively staged — verified the sprite/NPU hunks stay unstaged in the
   working tree), then snapshot the exact commit with `git archive HEAD` into
   `/home/jan/.local/state/symbiote/deploy/20260917-frame-watch/` and deploy with
   `symbiote-apply --source <that>`. Side effect to know: after this deploy, the
   `~/.pi/agent/extensions/*` symlinks point into the snapshot dir (that is how
   configurePi `${../}` paths resolve). Keep the snapshot dir; a later deploy from the
   main repo (after the sprite work is committed) will re-point them.
